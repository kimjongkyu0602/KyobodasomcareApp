## 웹사이트를 그대로 감싼 앱이 왜 반려되나 (4.2 최소 기능)

- Apple 은 "Safari 로 웹사이트를 열면 되는 것"을 앱으로 따로 올리는 것을 원하지 않습니다. 가이드라인 4.2 는 앱이 **단순히 웹사이트를 다시 포장한 수준 이상**의 기능·콘텐츠·사용 경험을 줘야 한다고 정합니다. ("not primarily a repackaged website")
- 심사관은 앱을 열어 보고 ① 모든 화면이 웹 페이지이고 ② 앱에서만 되는 일이 없으면 4.2(또는 4.2.2) 로 반려합니다. 이 경우 웹을 고쳐도 앱이 같으면 계속 반려됩니다.
- 그래서 이번에 **웹이 아닌 네이티브 화면**(온보딩, 더보기, 잠금 화면)과 **기기 기능**(알림 설정, Face ID 잠금, 공유, 전화)을 넣었고, 심사 메모에 심사관이 직접 확인하는 방법을 적었습니다.
- 그래도 반려되면 다음 후보: 앱에 받은 알림 목록(알림함), 건강검진 일정 캘린더 추가, 홈 화면 위젯 등 앱에서만 되는 기능.

## 남은 반려 위험

1. **회원탈퇴·개인정보처리방침 URL** — 없으면 거의 반드시 반려 (5.1.1). 웹팀 작업 1순위.
2. **테스트 계정 / 본인인증** — 심사자가 로그인하지 못하면 2.1 반려. 본인인증 없이 들어갈 수 있는 심사용 계정 권장.
3. **4.2 최소 기능** — 네이티브 온보딩·더보기·Face ID 잠금을 넣어 위험을 줄였지만, 주요 콘텐츠가 웹이라 위험이 완전히 없지는 않음. 반려되면 알림함 같은 앱 전용 기능 추가.
4. **간편인증 실제 완료 흐름** — 팝업이 열리는 구조는 수정했지만, 실제 인증 → 로그인 완료까지 테스트 계정으로 아이폰에서 한 번 확인 필요.
